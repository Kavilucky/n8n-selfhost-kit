ПРИВАТНЫЙ ПОМОЩНИК ПО УЧЁТУ ЧЕКОВ: фото чека боту, строка в таблице

Что получится: вы отправляете фото чека боту в Telegram. n8n передаёт снимок локальной модели Qwen (через Ollama), модель возвращает продавца, ИНН, дату, итог и позиции в формате JSON, n8n проверяет, что сумма позиций равна итогу, и дописывает строку в файл expenses.csv. Бот отвечает, что записал. Если сумма не сходится или поля не прочитались, бот просит сфотографировать чек ещё раз.
Это помощник по учёту, а не бухгалтер: налоговых советов он не даёт, ошибки возможны. Сверяйте суммы и храните бумажные чеки.
В архиве: Инструкция.txt, receipt_parser_workflow.json, expenses_template.csv, model_prompt_ru.txt, папка test_receipts (три синтетических чека, все данные вымышленные).
Проверено автором: логика узлов разбора ответа модели, проверки суммы и сборки CSV (на тестовых данных). Сам шаблон это заготовка: откройте каждый узел и проверьте параметры на вашей версии n8n.

------------------------------------------------------------
1. ЧТО НУЖНО
------------------------------------------------------------
  - n8n (запускается в Docker или установкой через npm).
  - Ollama на том же компьютере, где n8n (или доступная по сети).
  - Модель qwen2.5vl. По странице модели в Ollama: 3B занимает 3,2 ГБ, 7B (по умолчанию) 6,0 ГБ, 32B 21 ГБ; нужен Ollama версии 0.7.0 или новее. Для слабого компьютера берите 3B, но точность будет ниже.
  - Бот в Telegram.
  - Публичный HTTPS-адрес для вебхука Telegram (для локального n8n это туннель, см. шаг 4).

------------------------------------------------------------
2. OLLAMA И МОДЕЛЬ
------------------------------------------------------------
  1) Установите Ollama с официального сайта ollama.com.
  2) Скачайте модель командой:
       ollama pull qwen2.5vl:7b
     (для слабого компьютера: ollama pull qwen2.5vl:3b, тогда в узле «Qwen через Ollama» замените имя модели).
  3) Проверьте: ollama run qwen2.5vl:7b и отправьте любое сообщение.
Распознавание идёт на вашем компьютере: снимки чеков отправляются только модели на этом же компьютере. Фото до бота при этом доходит через серверы Telegram (это обычное сообщение боту).

------------------------------------------------------------
3. БОТ В TELEGRAM
------------------------------------------------------------
  1) В Telegram откройте @BotFather, команда /newbot, придумайте имя.
  2) Скопируйте токен бота: он понадобится в n8n. Токен никому не показывайте.

------------------------------------------------------------
4. N8N И ВЕБХУК
------------------------------------------------------------
  1) Запустите n8n (пример для Docker, подставьте свой публичный адрес вместо https://n8n.example.com):
       docker run -d --name n8n -p 5678:5678 -e WEBHOOK_URL=https://n8n.example.com/ -v n8n_data:/home/node/.n8n -v n8n_files:/home/node/.n8n-files n8nio/n8n
  2) Telegram отправляет сообщения вебхуком, поэтому адрес должен быть доступен из интернета по HTTPS. Для локального компьютера удобно открыть n8n через туннель (в ролике 07 разобран Cloudflare Tunnel; нужен домен в Cloudflare) и указать этот адрес в WEBHOOK_URL.
  3) Из контейнера n8n на Windows и macOS Ollama доступна по адресу host.docker.internal:11434 (он уже стоит в шаблоне). На Linux добавьте к docker run параметр --add-host=host.docker.internal:host-gateway и проверьте, что Ollama слушает сетевой интерфейс, доступный контейнеру. Если соединение не проходит, замените адрес в узле «Qwen через Ollama» на адрес вашего компьютера в локальной сети.

------------------------------------------------------------
5. ИМПОРТ И НАСТРОЙКА ВОРКФЛОУ
------------------------------------------------------------
  1) В n8n: Workflows, Import from file, выберите receipt_parser_workflow.json.
  2) Во всех узлах Telegram создайте учётные данные (Credential) с токеном бота.
  3) Проверьте узел «Qwen через Ollama»: адрес, имя модели, таймаут (на слабом железе распознавание идёт долго, таймаут 300 секунд заложен).
  4) Файл таблицы пишется по пути /home/node/.n8n-files/expenses.csv (папка файлов n8n; в примере docker run это том n8n_files). Если у вас другая установка, поменяйте путь в узле «Записать expenses.csv».
  5) Строки таблицы накапливаются в данных воркфлоу, поэтому ВКЛЮЧИТЕ воркфлоу переключателем Active: в ручном тесте накопление не сохраняется.
  6) Необязательно: узел «(необязательно) Google Sheets» отключён. Если включите его, данные таблицы уйдут в Google (облачный сервис).

------------------------------------------------------------
6. ПРОВЕРКА НА ТЕСТОВЫХ ЧЕКАХ
------------------------------------------------------------
  1) Отправьте боту фото из папки test_receipts как ФОТО (не как файл).
  2) Сверьте ответ бота с ожидаемыми итогами из test_receipts/README.txt.
  3) Чек 2 выцветший и размытый, чек 3 повёрнут: на них модель ошибается чаще, это нормально для проверки ветки «сфотографируйте ещё раз».
  4) Проверьте файл expenses.csv: он открывается в Excel и в LibreOffice (разделитель точка с запятой).
  5) Замерьте на своём компьютере точность и время: на русских чеках качество модели нужно проверять самим, автор цифр точности не заявляет.

------------------------------------------------------------
7. ОГРАНИЧЕНИЯ
------------------------------------------------------------
  - Выцветшая термобумага, мятые и тёмные снимки снижают точность; фотографируйте ровно, при хорошем свете, чтобы весь чек был в кадре.
  - Проверка «сумма позиций равна итогу» ловит часть ошибок, но не все (например, ошибку, которая случайно сохранила сумму).
  - Облачные модели и облачные таблицы передают данные провайдеру; при локальной Ollama и файле expenses.csv данные остаются у вас, кроме пути фото через Telegram.
  - Ollama Cloud структурированный вывод (параметр format) не поддерживает, используйте локальную Ollama.
  - Налоговые и бухгалтерские вопросы решайте с бухгалтером.

------------------------------------------------------------
8. ВТОРАЯ КОПИЯ
------------------------------------------------------------
Копируйте expenses.csv и бумажные или фото оригиналы чеков на внешний диск, например раз в неделю. Не выбрасывайте оригиналы, пока не проверили, что запись в таблице верна. Правило 3-2-1: три копии, два носителя, одна копия вне дома.
