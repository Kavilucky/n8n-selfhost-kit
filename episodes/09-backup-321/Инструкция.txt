АВТОБЭКАП ПО ПРАВИЛУ 3-2-1: KOPIA И RESTIC

Что получится: скрипт делает зашифрованные снапшоты вашей папки (фото, документы) на внешний диск и, если указать вторую копию, ещё в одно место. Первый снапшот сохраняет всё, следующие только изменившееся; одинаковые куски данных пишутся один раз (дедупликация). Шифрование идёт на вашем компьютере до записи: диск без пароля ничего не прочитает. Скрипт ничего не удаляет.
Правило 3-2-1: три копии данных (оригинал и две резервные), на двух разных носителях, одна копия вне дома.
В архиве: Инструкция.txt, backup_windows.bat, backup_linux.sh, backup_config.cmd (Windows), backup_config.sh (Linux), exclude.txt (что не копировать), папка Тестовая_папка (вымышленные файлы для проверки).
Основной инструмент Kopia (есть окно KopiaUI и командная строка), Restic второй вариант (только командная строка). Бесплатны сами программы (лицензии Apache 2.0 и BSD-2); внешний диск и облачное хранилище платные.

ЧТО ПРОВЕРЕНО АВТОРОМ (честно)
  - Windows 11, Kopia 0.23.1 и Restic 0.19.1, локальные репозитории на двух папках: первый и повторный снапшот, проверка (verify), восстановление с побайтным сравнением, исключение *.tmp, пути с русскими буквами и пробелами (в том числе в папке со скриптом), понятные ошибки (нет файла пароля, неверный пароль). 48 проверок и приёмка самого архива из распакованной папки, все пройдены.
  - backup_linux.sh проверен в Git Bash на Windows с теми же бинарниками (24 проверки), на живом Linux автор его не запускал.
  - НЕ проверялось: облачные хранилища (Backblaze B2 и другие), SFTP, запуск по расписанию, скорость копирования (скорость не измерялась и не сравнивалась).

------------------------------------------------------------
1. УСТАНОВКА
------------------------------------------------------------
Kopia: скачайте с официального сайта kopia.io (для Windows есть установщик KopiaUI и архив с kopia.exe). Для скриптов нужен файл kopia.exe (или kopia на Linux).
Restic: скачайте со страницы релизов github.com/restic/restic (архив для вашей системы; в нём один файл restic). Рядом на странице лежит файл SHA256SUMS: сверьте контрольную сумму архива перед запуском (в PowerShell: Get-FileHash архив.zip -Algorithm SHA256).
Положите нужный файл в любую папку и укажите её в TOOL_DIR в конфиге (или добавьте папку в PATH). Выбирать нужно один инструмент: TOOL=kopia или TOOL=restic.

------------------------------------------------------------
2. ПАРОЛЬ РЕПОЗИТОРИЯ (самое важное)
------------------------------------------------------------
  1) Придумайте длинный пароль.
  2) Сохраните его в текстовый файл, первая строка файла и есть пароль, например C:\backup-secret\repo_password.txt (Linux: ~/.backup-secret/repo_password.txt). Файл НЕ храните на диске с копией.
  3) Сохраните пароль ещё отдельно: в менеджере паролей и на бумаге в надёжном месте.
Пароль потерять нельзя: без него данные из копии восстановить невозможно (так сказано в документации Kopia, для Restic по той же схеме шифрования).

------------------------------------------------------------
3. НАСТРОЙКА КОНФИГА
------------------------------------------------------------
Windows: откройте backup_config.cmd в Блокноте. Сохраняйте файл в кодировке UTF-8 без BOM (так по умолчанию сохраняет Блокнот Windows 10 и 11): тогда русские буквы в путях работают.
Linux: откройте backup_config.sh в текстовом редакторе.
Значения:
  TOOL          kopia или restic.
  SOURCE_DIR    папка, которую копируем (например, фото и документы).
  REPO1         папка на ВНЕШНЕМ ДИСКЕ: сюда пишется копия 1 (это второй носитель). Репозиторий создаётся при первом запуске.
  REPO2         вторая копия вне дома (необязательно, но без неё правило 3-2-1 не выполнено): см. раздел 7.
  PASSWORD_FILE файл с паролем из раздела 2.
  TOOL_DIR      папка с kopia.exe или restic.exe, если они не в PATH.
Что не копировать, задано в exclude.txt (например, *.tmp, Thumbs.db): правьте под себя.

------------------------------------------------------------
4. ПРОВЕРКА НА ТЕСТОВОЙ ПАПКЕ (сделайте до реальных данных)
------------------------------------------------------------
  1) Укажите SOURCE_DIR на папку Тестовая_папка из архива, REPO1 на временную папку (не на ваш рабочий диск с данными).
  2) Запустите (Windows: двойной щелчок по backup_windows.bat или в командной строке backup_windows.bat; Linux: ./backup_linux.sh). Скрипт создаст репозиторий и сделает первый снапшот. В конце напишет OK.
  3) Измените любой файл в Тестовая_папка, добавьте новый и запустите снова: появится второй снапшот (в нём записано только изменившееся).
  4) Запустите проверку: backup_windows.bat verify (Linux: ./backup_linux.sh verify).
  5) Восстановите файл вручную (раздел 8) и откройте его.
Только после этого указывайте свои папки.

------------------------------------------------------------
5. ПЕРВЫЙ РЕАЛЬНЫЙ ЗАПУСК
------------------------------------------------------------
Подключите внешний диск, укажите свои SOURCE_DIR и REPO1 и запустите backup. Дальше запускайте регулярно (раздел 6). Скрипт только добавляет снапшоты и ничего не удаляет. Старые снапшоты Kopia прореживает по своим политикам; Restic копит их, пока вы сами не выполните команды forget и prune (см. документацию Restic, делайте осторожно).

------------------------------------------------------------
6. РАСПИСАНИЕ (автор не проверял)
------------------------------------------------------------
Windows (раз в сутки в 21:00, внешний диск должен быть подключён; подставьте свой путь):
  schtasks /create /sc daily /tn "Backup321" /tr "\"C:\backup\backup_windows.bat\"" /st 21:00
Linux (cron, раз в сутки в 21:00):
  0 21 * * * /home/name/backup/backup_linux.sh >> /home/name/backup321.log 2>&1
У Kopia расписание можно задать и в окне KopiaUI (вкладка Policies).
Проверьте, что при отключённом диске скрипт заканчивается ошибкой, а не пишет копию «в никуда».

------------------------------------------------------------
7. ПРАВИЛО 3-2-1 В НАСТРОЙКАХ
------------------------------------------------------------
  Копия 1 (носитель 2): внешний диск, REPO1.
  Копия 2 (вне дома): REPO2.
  Kopia: скрипт принимает в REPO2 папку на другом диске или сетевом диске; такой диск или NAS должен находиться вне дома (например, у родственников) или подключаться только на время копирования. Для облака (S3, Backblaze B2 и др.) используйте окно KopiaUI: создайте второй репозиторий нужного типа (Repository, выбор типа хранилища) и задайте расписание на вкладке Policies; скриптом это не настроено.
  Restic: в REPO2 можно указать любой адрес репозитория Restic: папку, sftp:пользователь@сервер:/путь, S3-совместимое хранилище (адрес вида s3:s3.регион.backblazeb2.com/бакет, ключи в переменных AWS_ACCESS_KEY_ID и AWS_SECRET_ACCESS_KEY; формат смотрите в разделе S3 документации Restic: облако автор не проверял).
  Облачное хранилище платное. Данные в нём зашифрованы на вашем компьютере до отправки.

------------------------------------------------------------
8. ПРОВЕРКА РАЗ В МЕСЯЦ И ВОССТАНОВЛЕНИЕ
------------------------------------------------------------
Раз в месяц: backup_windows.bat verify (читается случайные 5 процентов данных) и восстановите один файл вручную, чтобы убедиться, что он открывается.
Сначала в окне командной строки задайте пароль (Windows):
  Kopia:   set /p KOPIA_PASSWORD=<C:\backup-secret\repo_password.txt
  Restic:  set RESTIC_PASSWORD_FILE=C:\backup-secret\repo_password.txt
Kopia (конфиг репозитория kopia_repo1.config появляется рядом со скриптом после первого запуска):
  kopia --config-file=kopia_repo1.config snapshot list
  kopia --config-file=kopia_repo1.config snapshot restore ИДЕНТИФИКАТОР D:\restore
  (идентификатор снапшота берётся из списка; корневой идентификатор начинается с буквы k)
Restic:
  restic --repo E:\backup\repo snapshots
  restic --repo E:\backup\repo restore latest:/C/Users/Name/Pictures --target D:\restore
  Путь внутри снапшота пишется с диском как папкой (C:\Users\Name\Pictures превращается в /C/Users/Name/Pictures). Если восстановить путь целиком (restore latest --target ...), на Windows Restic может написать «Access is denied» про папку C:\Users и «Fatal: There were 1 errors»: файлы при этом восстанавливаются, но чистый результат даёт форма с подпапкой, как выше.
Linux: те же команды, пути вида /mnt/backup/repo и /home/name/Pictures.

------------------------------------------------------------
9. ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
------------------------------------------------------------
  - «PASSWORD_FILE ... empty»: файл пароля не найден или пустой, проверьте путь и первую строку.
  - «kopia not found» или «restic not found»: укажите TOOL_DIR или добавьте программу в PATH.
  - Неверный пароль: скрипт остановится с ошибкой и ничего не испортит; поправьте файл пароля.
  - Русские буквы в путях не читаются: сохраните backup_config.cmd в UTF-8 без BOM.
  - Если репозиторий создан на другом компьютере: скрипт сам подключится к существующему, нужен тот же пароль.
